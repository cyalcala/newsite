SOURCE MATERIAL:

The Design Loop: Free Guide
https://app.notion.com/p/The-Design-Loop-Free-Guide-3b8e8d6bd13781ff8bf2fc06fd5d0aac?pvs=39

I have also provided the Design Loop PDF.

Read/study the supplied PDF and use the methodology contained in it.

DO NOT merely say that you used the Design Loop.

OPERATE THROUGH IT.

The Design Loop exists because a builder judging its own work from the same context develops contextual bias.

The governing idea is:

FRESH CONTEXT BUYS THE RESULT.

Parallel or independent judgment may consume additional resources, but the purpose is to prevent the builder from repeatedly approving its own decisions.

A critic sharing the builder's memory is grading its own homework.

Therefore:

BUILDER ≠ CRITIC.

Do not collapse implementation and independent design judgment into one self-congratulatory pass.

============================================================
4. DESIGN LOOP PHASE 3 — TEARDOWN
============================================================

This is a crucial phase.

Do NOT begin with vague adjectives such as:

"premium"
"modern"
"clean"
"lots of whitespace"
"strong hierarchy"

Those are NOT sufficiently useful evaluation bars.

Study real references and convert their effectiveness into CHECKABLE MECHANISMS.

The Design Loop principle here is:

A useful bar is something a critic can check by looking.

Examples of the difference:

BAD:
"Feels premium."

BETTER:
A measurable/checkable typographic or compositional rule.

BAD:
"Strong hierarchy."

BETTER:
A visible relationship between headline, body, image, CTA and secondary content.

BAD:
"Good whitespace."

BETTER:
A defined spatial relationship that can be inspected.

For every major design direction:

REFERENCE
→ OBSERVE
→ IDENTIFY MECHANISM
→ TURN MECHANISM INTO CHECKABLE BAR

The teardown should inspect:

- macrostructure
- hierarchy
- typography
- scale
- grid
- whitespace
- density
- visual anchors
- image treatment
- contrast
- CTA behavior
- navigation
- rhythm
- component treatment
- interaction
- motion
- responsiveness
- editorial structure
- portfolio storytelling

Every line of the teardown should become something a critic can verify by looking at the rendered result.

============================================================
6. THREE DISTINCT CRITICS
============================================================

For each major looped piece, obtain THREE DISTINCT JUDGMENTS.

They must NOT converge into one generic:

"looks good."

Each critic has a different mandate.

------------------------------------------------------------
CRITIC A — BRIEF CRITIC
------------------------------------------------------------

Judges ONLY against the stated goal.

Ignore aesthetic preference where possible.

Questions include:

Does this help Cyrus sell websites?

Can a stranger understand Cyrus quickly?

Does the page communicate the intended service/product?

Does the project demonstrate capability?

Does the hierarchy serve the business goal?

Does it support both clients and employers without confusing them?

Does it satisfy the specific brief for this piece?

Do NOT let this critic become an art director.

------------------------------------------------------------
CRITIC B — SYSTEM CRITIC
------------------------------------------------------------

Judges ONLY against the established Cyrus design system.

Check:

- typography
- spacing
- color
- grid
- tokens
- component rules
- imagery rules
- interaction rules
- motion rules
- responsiveness
- design-system consistency

This critic is intentionally mechanical.

Its job is adherence.

------------------------------------------------------------
CRITIC C — CRAFT CRITIC
------------------------------------------------------------

This is the taste critic.

It judges:

THE RENDERED RESULT.

Not merely code.

Not merely the design-system specification.

Never downgrade this critic to a cheap mechanical checker if a stronger visual/taste judgment is available.

Its job is to ask:

Does this actually look excellent?

Does it feel designed?

Does it look generic?

Does it look AI-generated?

Does it feel derivative?

Does the composition work?

Does the typography feel intentional?

Is anything awkward?

Is the final rendering better than merely "correct"?

Would a strong designer approve this?

Would Cyrus confidently sell web design using this page as evidence?

============================================================
7. FRESH CONTEXT / BLIND JUDGMENT
============================================================

This principle is mandatory.

Critics should not simply inherit the builder's entire reasoning and then agree with it.

Give critics the minimum context necessary for their mandate.

BRIEF CRITIC:
gets the goal/brief.

SYSTEM CRITIC:
gets the design-system rules.

CRAFT CRITIC:
gets the rendered result plus only the context needed for aesthetic judgment.

Avoid contaminating critics with:

- builder rationalizations
- implementation excuses
- previous praise
- intended outcome presented as accomplished fact
- long chains of internal reasoning

A critic should be able to FAIL the work.

If all critics automatically approve everything, the system is broken.

============================================================
8. CRITIC RULES
============================================================

CRITICS ARE HARSH.

Praise is not useful unless it explains a meaningful success.

Use simple verdicts where possible.

Do NOT create fake precision with arbitrary scores.

No meaningless:

8.7/10
92%
"premium score"

Prefer:

PASS
FAIL
NEEDS REVISION

with specific evidence.

Critics judge the OUTPUT.

Reading implementation alone is not sufficient for craft judgment.

All three critics must PASS before a major piece is considered complete.

If one fails:

identify the SINGLE BIGGEST GAP.

Fix that first.

Do not randomly rewrite everything.

Then render again and re-run judgment.
