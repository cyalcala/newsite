A useful starting point.

Finding remote work often means jumping between job boards, checking location restrictions and opening the same listing twice. The Hub is my response: a focused index that helps Filipino freelancers find relevant opportunities and follow them back to the original source.

The interface is the easy part to see.

The public board organizes work into categories and connects it to a company directory. Visitors can explore the opportunity, then leave for the original application. No account or résumé upload is required.

Behind that surface, I built a workflow for collecting permitted public listings, handling duplicates, checking geographic relevance and maintaining source health. Keeping information useful is part of the product design.

From source to opportunity.

01 / COLLECT

Find the opening.

Read supported public feeds, APIs and applicant-tracking sources.

02 / ORGANIZE

Make it useful.

Normalize, deduplicate and screen for location relevance with AI-assisted triage.

03 / CONNECT

Get to the source.

Publish the listing with attribution and a path to its original application.

What this work demonstrates.

Information architecture, a responsive public interface, data workflows and the less visible work of maintaining a useful product. The site and the system have to agree about what belongs on the page.

This is an independent portfolio product. Listings and source availability change. A configured refresh schedule is not a guarantee that every source is current; applicants should check the original employer listing.
Under the hood: architecture and boundaries

The production path uses Astro and TypeScript with Cloudflare Pages and D1. A scheduled Worker calls the ingestion endpoint; normalization, geographic screening and triage feed the public board. Maintenance includes link checks, stale-listing cleanup and source-health records.

Older framework experiments remain in the repository as history. The public product does not offer payments, user accounts or automatic applications. Planned source-replenishment work is documented separately from deployed behavior.
